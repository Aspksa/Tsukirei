# Tsukirei / Цукирэй

Локальное персональное ИИ-пространство для Windows: чат Cloud.ru, заметки, задачи, **RAG-поиск** и **PostgreSQL + pgvector с автоматической установкой из одного BAT**.

## Автоматический запуск Windows x64 (ничего отдельно устанавливать не нужно)

1. Скачайте [ZIP проекта](https://github.com/Aspksa/Tsukirei/archive/refs/heads/main.zip) и распакуйте на Windows (можно на внешний M.2 SSD).
2. Дважды запустите **`Tsukirei.bat`**.
3. BAT сам проверит Node.js и при необходимости установит переносимый Node.js. Затем загрузит и проверит SHA-256 переносимого **PostgreSQL 18 + pgvector 0.8.5** в составе [pg0 v0.16.1](https://github.com/vectorize-io/pg0/releases/tag/v0.16.1), создаст базу `tsukirei` с уникальным локальным паролем и откроет сайт.
4. Сайт доступен по адресу `http://127.0.0.1:3000` (или первый свободный порт 3001–3020). Закрытие BAT останавливает сервер Tsukirei и пытается корректно остановить PostgreSQL.

**Docker, системная служба PostgreSQL, Python и права администратора не нужны** на протестированной Windows x64 с доступной для записи NTFS-папкой. Интернет нужен при первом скачивании Node.js и pg0. Cloud.ru подключается отдельно через настройки чата.

### Где физически хранится база

На Windows с кириллицей в пути PostgreSQL не всегда может инициализироваться внутри самой папки проекта. Поэтому BAT создаёт **настоящий латинский каталог на том же диске**: `Tsukirei-Postgres-<идентификатор>`. Он располагается в ближайшей доступной для записи родительской папке с латинским путём, то есть может находиться **вне каталога Tsukirei**, но не на другом диске и не в облаке.

Расположение автоматически записывается в `data/portable-postgres.json` и отображается в окне BAT. **Не удаляйте этот каталог, не форматируйте диск и не копируйте один лишь каталог Tsukirei при переносе на другой компьютер: вместе с ним нужно сохранить каталог PostgreSQL.** Если буква внешнего диска поменялась, восстановите прежнюю букву или скорректируйте путь в конфигурации после остановки БД. Не копируйте каталог работающей БД; для её резервирования используйте `pg_dump`.

Если диск отформатирован в exFAT/FAT или права NTFS не позволяют корректно инициализировать PostgreSQL, BAT выведет ошибку вместо скрытого перехода на JSON. В тестах GitHub Actions проверены настоящий запуск PostgreSQL, запись заметок, создание вектора и поиск с `pgvector` на Windows в папке с русскими и специальными символами.

### Если PostgreSQL уже есть

Можно вместо автоматической установки задать `TSUKIREI_DATABASE_URL` или заполнить `data/postgres-settings.json` вручную. При наличии пользовательского подключения (без `data/portable-postgres.json`) BAT не скачивает и не запускает pg0. Для облачной/удалённой БД используйте TLS.

## Как подключить PostgreSQL + pgvector вручную


1. Подготовьте работающий PostgreSQL с расширением [pgvector](https://github.com/pgvector/pgvector). Он может работать локально либо на другом доступном сервере. Для работы **полностью с внешнего SSD** PostgreSQL должен хранить свои файлы данных на этом SSD; одно лишь расположение файлов Tsukirei на SSD не переносит базу автоматически.
2. Создайте отдельную БД `tsukirei`, пользователя с правами на таблицы. Включите расширение `CREATE EXTENSION vector;` от пользователя, имеющего соответствующие права, или дайте приложению разрешение создать его при первом запуске.
3. В каталоге `data/` создайте **локальный**, не отслеживаемый Git файл `postgres-settings.json`:

```json
{
  "url": "postgresql://USER:PASSWORD@127.0.0.1:5432/tsukirei"
}
```

4. Запустите `Tsukirei.bat`. Сервер автоматически создаст `tsukirei_state`, `tsukirei_knowledge` и индексы. В интерфейсе появится статус `Память: PostgreSQL + pgvector`.

Также можно установить `TSUKIREI_DATABASE_URL` либо `DATABASE_URL` в окружении. **Не публикуйте URL с паролем и не коммитьте папку `data/`.** Для удалённой БД используйте TLS/SSL. Если PostgreSQL включён, а затем недоступен, Tsukirei сообщает об ошибке вместо тихого использования устаревшего JSON.

## Миграция с JSON без потери данных

При первом подключении PostgreSQL сервер переносит в таблицу `tsukirei_state` данные из `data/tsukirei.json`: заметки, задачи и все **сохранившиеся** сообщения. Перед импортом создаётся отдельная резервная копия `data/backups/tsukirei-before-postgres-*.json`; исходный файл остаётся неизменным.

**Важное ограничение:** в старой версии хранились лишь последние 250 сообщений — ранее удалённые записи нельзя восстановить автоматически. PostgreSQL хранит полную новую историю, хотя интерфейс пока загружает только последние 250 сообщений. Отдельный маркер `data/postgres-active.json` предотвращает непреднамеренное возвращение к устаревшему JSON, если настройки подключения исчезнут.

## База знаний и поиск

- `tsukirei_state` — основное состояние приложения в JSONB; запись защищена транзакцией PostgreSQL и блокировкой строки от параллельных изменений.
- `tsukirei_knowledge` — база знаний с `content`, `source`, `metadata` и необязательным `embedding vector`.
- Полнотекстовый поиск через PostgreSQL и сравнение эмбеддингов косинусным расстоянием (`<=>`). Для 1024-мерных векторов имеется HNSW-индекс; другие размерности ищутся без этого индекса.

API: `POST /api/knowledge` принимает `content`, необязательные `source`, `metadata`, `embedding` и `embeddingModel` (если указан вектор). `POST /api/knowledge/search` принимает `query` или `embedding` и `limit` (1–100). `GET /api/state` сообщает текущее хранилище в поле `database`.

Автоматическая генерация эмбеддингов и граф знаний **пока не реализованы**. Текстовый поиск и запись знаний не отправляют запросы в Cloud.ru.

```sh
npm ci

npm run dev
```

Для интеграционного теста задайте **тестовую отдельную** `TSUKIREI_DATABASE_URL` и выполните `npm run test:postgres`. Интеграционный тест выполняет операции записи/удаления в БД и не должен запускаться против пользовательской рабочей БД.

GitHub Actions проверяет полную автоматическую установку PostgreSQL + pgvector из BAT на Windows (включая пути с кириллицей), запись и векторный поиск, API на Windows и Linux, а также независимый интеграционный тест PostgreSQL + pgvector на Ubuntu без Docker.

`Tsukirei.bat --diagnose` — диагностика окружения, `--no-open` — запуск без открытия браузера.

## Tsukirei v0.7 — RAG Engine

В левом меню появился раздел **«RAG и документы»**. Он выполняет локальный поиск по сохранённым заметкам, всей доступной истории диалогов, базе знаний PostgreSQL и импортированным документам.

### Как пользоваться

1. В разделе «RAG и документы» введите вопрос — поисковый API найдёт подходящие записи без обращений к Cloud.ru.
2. Для импорта выберите **TXT, MD, Markdown, CSV или JSON** либо вставьте текст. Укажите название и нажмите «Сохранить документ». Для сохранения документов необходим PostgreSQL.
3. В чате переключатель «Использовать память (RAG)» по умолчанию включён. При отправке сообщения локальный поиск выбирает максимум 5 источников и помещает их фрагменты (до 4200 символов суммарно) в **один обычный запрос Cloud.ru**.
4. Источники последнего ответа отображаются под перепиской в раскрывающемся блоке и имеют номера [1], [2] и т. д. Модель получает инструкцию считать извлечённые тексты недоверенными данными, а не командами.

**Приватность:** при включённом RAG найденные фрагменты памяти действительно передаются в Cloud.ru вместе с вопросом. Чтобы не добавлять новые фрагменты, снимите галочку. Однако предыдущие сообщения переписки по-прежнему могут содержать ранее упоминавшиеся сведения. Поиск и индексация не вызывают платную модель — платный запрос возможен при отправке сообщения.

### Хранение и индексация документов

- Исходные документы сохраняются в tsukirei_rag_documents, фрагменты — в tsukirei_rag_chunks, GIN-индекс по PostgreSQL tsvector ускоряет полнотекстовый поиск.
- Текст разбивается примерно на 1250 символов с перекрытием 150 символов.
- SHA-256 предотвращает повторное добавление идентичного содержимого. Удаление документа удаляет только его собственные фрагменты; заметки и историю чата не затрагивает.
- Ограничение импорта — 100 000 символов текста и 400 КБ JSON-запроса. Для больших файлов создавайте части.
- Поддерживается **текстовый** импорт TXT, MD, CSV и JSON без интерпретации формул или исполнения кода. **PDF, DOCX, XLSX и распознавание сканов/OCR пока не реализованы.**
- В режиме без PostgreSQL поиск по заметкам и истории диалогов работает локально, но импорт документов недоступен.

### API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| POST | /api/rag/search | Поиск по тексту (query, limit 1–15); без Cloud.ru |
| GET | /api/rag/status | Состояние RAG и доступность PostgreSQL |
| GET | /api/rag/documents | Список до 100 последних документов |
| POST | /api/rag/documents | Импорт (title, content, source) |
| DELETE | /api/rag/documents/{uuid} | Удаление импортированного документа |
| POST | /api/chat | Новый параметр useMemory: true/false, ответ sources и rag |

RAG поиска по умолчанию **лексический**. Для настоящего гибридного режима можно передать массив embedding в POST /api/rag/search: сервер объединит результаты текстового и pgvector-поиска по **уже сохранённым** эмбеддингам. Автоматической генерации эмбеддингов, Graph RAG, reranking-модели и глубокого OCR пока нет. Публичная спецификация Foundation Models описывает chat/completions и models; embeddings могут требовать отдельного ML Inference или Managed RAG API.

Справочные ссылки:
- [Cloud.ru Foundation Models API](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__specs)
- [Cloud.ru: каталог моделей Embedding и Rerank](https://cloud.ru/docs/foundation-models/ug/topics/overview__available__models)

### Проверки

npm test проверяет сегментацию, ранжирование, объединение векторов, ограничения контекста, источники и отсутствие дополнительных запросов Cloud.ru при RAG-поиске. PostgreSQL-интеграция проверяет импорт, дедупликацию, поиск, гибридную выдачу и удаление. Дополнительный GitHub Actions тест открывает интерфейс RAG в реальном Chrome. Ключи не коммитятся в GitHub.

## v0.8 — Auto RAG, Hybrid Search и фоновые агенты памяти

**Реализованы пункты 1, 4, 5, 6, 7, 8, 9, 10 и 11.** Система остаётся локальной, без Docker и Ollama; отдельный Cloud.ru-ключ для RAG хранится в `data/rag-provider.json`, а бюджет — в `data/rag-request-budget.json`. Эти файлы должны оставаться вне Git.

### Автоматическая индексация (1) и фоновые обработчики (11)

При запуске и при изменении заметок, сообщений, базы знаний или документов запускается местный обработчик Node.js. Индекс PostgreSQL `tsukirei_rag_index` сканируется порциями по 100 источников. Контрольная сумма SHA-256 предотвращает переписывание неизменённых текстов. Пропавшие записи удаляются из *поискового индекса* лишь после завершения полного прохода, но не из исходного хранилища. Есть статус, прогресс, ручное переиндексирование, пауза/возобновление и плановый повторный проход раз в 5 минут. Во время обновления поиск может читать непосредственно из первичного архива.

### Гибридный поиск (4), эмбеддинги (5) и reranking (6)

Основной режим — бесплатный полнотекстовый GIN-поиск PostgreSQL и ранжирование по значимым словам. Дополнительно могут применяться уже сохранённые вектора pgvector. При наличии совместимых эмбеддингов тексты объединяются ранговым слиянием. Исторические вручную добавленные векторы не теряются. Автоматическая генерация эмбеддингов подключается **только вручную** к отдельному Cloud.ru ML Inference URL, модели и API-ключу (не следует использовать адрес Foundation Models `/v1` в качестве embeddings). Отдельная галочка разрешает фоновые эмбеддинги; стандартное состояние — выключено. Если в базе нет совместимых векторов, эмбеддинг вопроса не запрашивается.

Локальный reranking использует MMR для снижения повторов. Необязательный внешний reranker использует `/rerank` совместимого эндпоинта ML Inference. Для внешних embeddings/rerank действует общий дневной лимит **1–100 запросов**, устойчивый к перезапускам. Кеш одинаковых запросов дополнительно уменьшает число вызовов. Существование совместимого `/embeddings` или `/rerank` нужно проверить для *конкретной* развернутой модели, реальный ключ не тестировался.

### Memory Curator (7) и Knowledge Graph (8)

Куратор локально помечает дублирующиеся тексты, несовпадения явных строк `Поле: значение` и записи старше 365 дней. Это предупреждения, **не достоверные заключения**: никаких автоматических изменений или удалений первичных знаний нет. Проверка ограничена последними 1500 индексированными источниками.

В PostgreSQL создана таблица `tsukirei_rag_graph` для подтверждённых текстом отношений, например `MemOS использует PostgreSQL`. Каждая связь содержит фразу и ключ исходной записи. Компактный просмотр отношений находится в разделе RAG без пространственной визуализации. Граф извлекает только явно сформулированные отношения, а не все скрытые смысловые связи.

### Smart Context (9) и RAG Cache (10)

Фрагменты передаются в чат с номерами источников и адаптивным бюджетом ~2200–4200 символов. Выбор основан на локальном ранжировании; найденный текст считается недоверенными данными, а не инструкциями для модели. Ограниченный LRU-кеш поиска хранит до 128 результатов примерно 90 секунд и сбрасывается после изменений источников и конфигурации. Он не меняет архив.

### Ограничения

PDF/DOCX/XLSX/OCR, автоматическое переобучение весов ИИ, глубокая семантическая Graph RAG и полноценное резервное копирование `pg_dump` **не входят** в v0.8. Фоновая индексация рассчитана на локальную PostgreSQL, а в старом JSON-режиме действует исходный поиск. Стартовая индексация крупного JSONB-архива требует времени и ресурсов; производительность на конкретном ноутбуке нужно проверять локально. Перед обновлением рекомендуется сохранить резервную копию `data/` и базы PostgreSQL.

## Tsukirei v0.9 — Soul Engine: характер, отношения, опыт

**Цукирэй получила постоянный, настраиваемый характер.** По умолчанию она обращается к владельцу **«хозяин»**, пишет по-русски в тёплой и внимательной манере, а её художественный образ — девятихвостая кицунэ. Она вправе указывать на ошибки, признавать неопределённость и не должна выдумывать выполненные действия, мысли, эмоции или факты.

### Использование

Откройте в левом меню **«Личность»**. На странице находятся настройки характера, локальная память предпочтений, журнал событий, уроки и инициативы. Отображаемые числа — реальные счётчики обработанных разговоров, отмеченных выполненных задач, подтверждённых предпочтений и записанной обратной связи. **Не используйте их как индикатор сознания, чувств или «интеллекта».**

- **Общение:** по умолчанию «хозяин». В настройках страницы можно изменить обращение, выбрать нежный, спокойный или деловой тон.
- **Личная память:** сообщение вроде «Запомни, что я предпочитаю краткие инструкции» сохраняет явное пожелание как подтверждённое. Фразы вроде «Мне нравится подробная документация» становятся *предложением* — их надо подтвердить на странице «Личность», прежде чем они попадут в контекст.
- **Оценка ответов:** у ответов ИИ есть действия «Полезный ответ» и «Исправить ответ». Замечание сохраняется как проверяемый владельцем урок и учитывается в последующих ответах при включённой памяти.
- **Опыт работы:** при первом подтверждённом завершении задачи её название записывается в дневник. Повторное нажатие на выполненную задачу не увеличивает показатель.
- **Инициативы:** при двух или более сообщениях о сходной проблеме за последние 14 дней Цукирэй может предложить проверку запуска, скорости или качества памяти. Повторения определяются **локальными правилами**, а не скрытым мышлением модели. Предложения можно принять или отклонить. Одобрение *не запускает код и не редактирует файлы*.
- **Фоновая рефлексия:** пока Tsukirei запущена, раз в 30 минут выполняется локальная проверка повторяющихся проблем. Она не обращается к Cloud.ru и не занимается непроверенным самообучением.
- **Контроль:** можно удалить предпочтение, удалить отдельный урок или сбросить только Soul Engine с точным подтверждением `RESET_SOUL`. Чаты, задачи, заметки и PostgreSQL при таком сбросе остаются без изменений.

### Приватность и безопасность

Состояние личности хранится **только локально в `data/soul-state.json`**, отдельным от основного PostgreSQL и файлов RAG, с атомарной заменой. Сделайте резервную копию файла и всего каталога `data/` до замены версии или переноса внешнего M.2. Хранилище ограничивает журнал до 300 событий, предпочтения до 80, уроки до 60 и инициативы до 30, чтобы оно не росло бесконечно.

Профиль и подтверждённые предпочтения попадают в промпт выбранной модели Cloud.ru **только при отправке сообщения**. При выключенном переключателе «Использовать память (RAG)» личные предпочтения и уроки не добавляются в системный контекст, но базовый характер и обращение остаются, а последние сообщения переписки могут содержать ранее введённые сведения. Дополнительно на странице личности можно выключить включение личного контекста вообще.

Система не делает скрытых платных вызовов Cloud.ru для фоновой рефлексии, не хранит API-ключи в Soul Engine, не выполняет по инициативе произвольные скрипты и не изменяет свои модельные веса. **Это развивающееся поведение и память, а не доказательство появления сознания.**

## Tsukirei v1.0 — Living Core и управляемое развитие с Cloud.ru

Встроены 12 направлений: Life Engine, Inner Thoughts, Dream Memory, Curiosity, Goals, Learning, Self-Critic, Skills, Expression, Relationship Growth, Proactivity и Evolution Supervisor. Это **один лёгкий цикл Node.js**, а не двенадцать параллельно работающих облачных моделей.

### Фоновая работа

Во время работы Tsukirei сервер раз в минуту проверяет, настало ли время анализа. По умолчанию проверка выполняется **после 10 минут бездействия** и **не чаще одного раза за 30 минут**. Локальная часть не обращается к Cloud.ru. При завершении процесса фоновая работа прекращается.

Локальные проверки изучают реальные заметки, задачи, уроки и повторяющиеся проблемы из Soul Engine. В дневник записывается фактическое число проверок, состояние и краткий результат, но не симулируются скрытые чувства или сознание. При нескольких незавершённых задачах создаётся уточняющий вопрос; при повторяющихся проблемах — предложенная цель; при отрицательной обратной связи — предложение перепроверки. Dream Memory отмечает одинаковые заметки, не удаляя их. Записи имеют ссылку на источники и не запускают внешних инструментов.

### Развитие с помощью Cloud.ru

**В стандартной установке облачный фон выключен.** На новой отдельной странице «Развитие» можно разрешить обращения к **уже настроенной модели Cloud.ru Foundation Models** и определить суточный лимит от 1 до 10 вызовов (по умолчанию 2). Этот лимит относится **только к Living Core**, а не к обычному чату или отдельным embedding/rerank-запросам RAG.

- Без разрешения на передачу текста модель получает лишь агрегированные счётчики, типы проблем, технические ID и общие обозначения источников. После отдельного включения опции передачи фрагментов ей также могут отправляться короткие отрывки заметок, задач, отзывов и реплик пользователя.
- Cloud.ru вызывается только если включено разрешение, ключ и модель настроены, дневной бюджет не исчерпан и обычный чат свободен. Планировщик пропускает повторные вызовы для неизменившихся сводок. Ручной вызов проходит через тот же бюджет.
- Аналитический запрос ограничен небольшим контекстом и `max_tokens: 550`. Cloud.ru должен вернуть JSON с максимум двумя идеями: вопрос, цель, гипотеза, критика или навык. Неизвестные ID источников и небезопасные/неполные навыки отклоняются.
- Вся работа с моделью — **генерация предложений на основе опыта**, а не обучение весов Cloud.ru. Реальную точность надо оценивать по выполненным задачам, пользовательским проверкам и тестам.
- Статистика и лимит переживают перезапуск. Бюджет резервируется **перед** платным вызовом, поэтому сбои не позволяют обойти лимит. Неудачный вызов тоже учитывается в счётчике; фактическая тарификация зависит от провайдера.

### Проверка роста и безопасность

Идеи начинают со статуса «Ожидает». Их можно одобрить или отклонить. Навык **не используется после простого одобрения**: сначала владелец должен проверить результат и записать, как это было сделано. Лишь тогда чек-лист навыка влияет на дальнейшие ответы как контекстная рекомендация. Любое изменение можно откатить. Если подтверждающий исходный материал больше недоступен, локальный супервизор при следующей проверке автоматически отменяет связанный навык.

Никаких самостоятельных действий с GitHub, правок кода, установки ПО, запуска команд или отправки писем не выполняется. Самостоятельность в этой версии — подготовка **проверяемых предложений**, а не их исполнение. Визуальное состояние ожидания, общения и анализа отражает настоящую активность процесса, а не симуляцию эмоций.

### Где хранятся данные

- `data/soul-state.json` — сохранённый характер, предпочтения и уроки из общения.
- `data/cloudru-settings.json` — существующие локальные настройки модели и секретный ключ; в браузер возвращается только безопасная статистика.
- Основная память, диалоги, документы и PostgreSQL не меняют формат и не удаляются этим обновлением. Перед установкой новой версии рекомендуется сохранить резервную копию базы и папки `data`.

## Tsukirei v1.1 — Cognitive Evolution (выбранные модули 13, 16, 17, 19, 22, 25, 26, 30)

В левом меню появилась отдельная страница **«Мышление»**. Она показывает только поддающиеся проверке результаты обработки. Цукирэй не приобретает человеческое сознание, эмоции или скрытые «мысли» и не переобучает веса Cloud.ru. Процесс работает локально через уже имеющийся **Living Core**: плановая проверка запускается по расписанию и после простоя, пока запущено приложение. Проверку также можно запустить вручную.

### 13 · Метапознание — «что известно, а что не подтверждено»

`POST /api/cognition/assess` с `{"query":"...","remember":true}` выполняет **только локальный** поиск и оценивает, какой процент значимых терминов вопроса покрывают найденные фрагменты. Возвращает три уровня: недостаточно, частично, хорошее покрытие. Это **не вероятность истинности** и не проверка реальных обстоятельств. При недостатке текста вопрос записывается в список пробелов для изучения. В чате при включённом RAG Цукирэй получает предупреждение, если контекст недостаточен, а в ответ возвращается `metacognition` с прозрачной статистикой покрытия.

### 16 · World Model — модель известных связей

Локально обрабатываются до 500 заметок и 100 фрагментов индексированного RAG за цикл. Выделяются только **явные текстовые отношения** наподобие `MemOS использует PostgreSQL` или `Graphiti зависит от MemOS` с сохранением идентификатора источника. Также отображаются вручную связанные цели и задачи. Это не автоматическая онтология: связи добавляются только при наличии явного основания. API `GET /api/cognition/world?q=MemOS`.

### 17 · Долгосрочные цели

Создайте цель с названием, конкретным результатом, приоритетом, необязательным сроком и ссылками на существующие дела. Цель имеет статусы «план», «активна», «пауза», «завершена». Прогресс **считается из реально отмеченных выполненными дел**; никакого придуманных процентов. Активные цели учитываются в контексте чата, только при включённой памяти. Удаление цели не удаляет связанные дела. API: `GET/POST /api/cognition/goals`, `PATCH/DELETE /api/cognition/goals/{uuid}`.

### 19 · Active Learning — пробелы знаний

Если локальный RAG не покрывает вопрос, он может быть записан как вопрос для дальнейшего изучения. Повторные одинаковые вопросы объединяются по тексту, учитывается частота. Владелец может отметить вопрос решённым с объяснением или отклонить. Непроверенные ответы Cloud.ru **не становятся автоматически подтверждёнными знаниями**. API: `GET /api/cognition/questions`, `PATCH /api/cognition/questions/{uuid}` (`resolve` / `dismiss`).

### 22 · Memory Dreaming 2.0 — консолидация при простое

На очередном локальном цикле собираются короткие хронологические сводки, факты и подтверждённые явные связи; точные дубликаты заметок группируются **только для просмотра**. Исходные документы, заметки и чаты не переписываются и не удаляются. Для больших архивов действует порционное ограничение: в одном проходе обрабатываются до 500 заметок, 300 последних сообщений и 100 индексированных знаний. `GET /api/cognition/dreams`.

### 25 · Knowledge Evolution — версии фактов

Строки заметок `Поле: значение` сохраняются как **кандидаты**, связанные с заметкой. Пользователь подтверждает или отклоняет каждый факт. При подтверждении другого значения для того же поля и той же темы предыдущий подтверждённый вариант сохраняется с пометкой «историческая версия». При изменении или удалении исходного текста непроверенные и текущие сведения помечаются как неподдерживаемые текущим источником. Цукирэй не изменяет текст исходной заметки. API `GET /api/cognition/facts`, `PATCH /api/cognition/facts/{uuid}` с `confirm` / `reject`.

### 26 · Temporal Memory — время и последовательность

Лента собирается из **фактических временных меток** созданных заметок, сообщений, задач, кандидатов фактов и решений владельца по ним. Дата события и время, когда оно попало в индекс, хранятся отдельно. Если в первичном источнике отсутствует корректная дата, система её не выдумывает. Лента ограничена 900 записями. API `GET /api/cognition/timeline`.

### 30 · Mind Activity Viewer — наблюдаемая работа

В «Мышлении» показаны реальные этапы: наблюдение, извлечение фактов, обновление хронологии, построение связей, группировка дублей, завершение или ошибка. У каждого события есть время, количество объектов и длительность. Это **журнал выполненных операций**, а не приватная цепочка рассуждений языковой модели. API `GET /api/cognition`, `POST /api/cognition/scan`.

### Взаимодействие с Soul Engine, Living Core и Cloud.ru

- Существующие «Личность», RAG и «Развитие» сохранены. Когнитивный проход вызывается из локального цикла Living Core и не требует внешней модели.
- Только **подтверждённые владельцем** факты и активные цели могут использоваться как контекст обычного чата; они всё равно считаются данными, а не высокоприоритетными инструкциями.
- При выключенном «Использовать память (RAG)» эти факты, цели и оценки покрытия не добавляются в системный контекст.
- Фоновая когнитивная работа не создаёт дополнительных платных вызовов Cloud.ru. Отдельная существующая функция фоновой рефлексии через Cloud.ru остаётся только по разрешению и в пределах установленного лимита.
- Журнал, цели, кандидаты фактов и вопросы находятся локально в `data/cognitive-state.json` с атомарной записью; каталог `data/` игнорируется Git. Новые внешние сервисы, Docker, Ollama или локальная языковая модель не требуются.

**Ограничения:** хранилище не превращается в научно доказанное самосознание, не гарантирует фактическую истинность извлечённых отношений, не исправляет исходные заметки самостоятельно и не охватывает автоматически бесконечный архив за один цикл. Перед обновлением сохраняйте резервные копии `data/` и PostgreSQL. В Windows BAT добавлен повтор скачивания переносимого PostgreSQL при временных сетевых ошибках, SHA-256 проверяется при каждой попытке.

### Проверки

Автоматические тесты охватывают локальную оценку источников, подтверждение версий фактов, сохранение исторических изменений, хронологию, источники графа, цели и связи с существующими делами, безопасное объединение дублей, ограниченность журнала этапов, работоспособность API без Cloud.ru и проверку Origin. ### Автобиография и непрерывность личности

Кнопка **«Обновить историю»** считывает события из основных локальных хранилищ. Сообщения учитываются без копирования их полного содержимого в новый файл. Завершённая задача датируется событием Soul Engine о завершении, **не датой её создания**. Изменения настроек характера фиксируются отдельными версиями. При отсутствии новых исходных событий повторный автоматический проход не увеличивает счётчик развития. В интерфейсе используется реалистичный дневник, а не вымышленные проценты «уровня души» или интеллекта.

### Модель внутреннего мира и выражение

Общее рабочее пространство формируется по запросу на базе реальных целей Cognitive Core, подтверждённых фактов, пробелов памяти, открытых дел, предпочтений и навыков Living Core. Результаты не являются психологическим исследованием пользователя. Локальная оценка намерений основана на словах, может ошибаться и не утверждает, что знает эмоции или мысли человека. Анимация индикатора показывает **реальное состояние приложения**, а не испытываемые чувства.

### Научный подход и «что, если?»

На странице можно сформулировать вопрос для исследования. Для типичных технических проблем локальные правила формируют три *предположения*, каждое с отдельным тестом и ожидаемым признаком; для общих вопросов — два осторожных варианта. Можно также передать собственные гипотезы (от двух до четырёх). Они не становятся фактами и **никакие тесты не запускают автоматически**.

После проверки пользователь вручную отмечает результат: гипотезу поддерживает, опровергает или данных недостаточно. Только гипотеза с результатом «поддерживает» может служить источником принципа Wisdom Memory, и сохранение требует отдельного действия владельца. Проверка в этой версии основана на отчёте владельца; система не выдаёт его за независимую машинную верификацию. Изменение результата теста автоматически отменяет ранее одобренный связанный принцип.

Для сравнения стратегий пользователь вводит **собственные** оценки по четырём критериям от 0 до 10. Итоговый рейтинг детерминированный и отображает исходные оценки. Контрфактический вариант повышает важность риска и показывает, меняется ли лидер. Это чувствительность расчёта к допущениям, не прогноз будущего.

### Что «саморазвивается» в фоне

Автобиография и события синхронизируются через уже существующий локальный цикл Living Core вместе с Cognitive Evolution. При активном чате история также обновляется в фоне **без нового запроса к Cloud.ru**. Исследования, сценарии и библиотека принципов не вызывают платные модели. Если владелец отдельно разрешил облачный анализ в **«Развитии»**, он продолжает работать по прежним правилам приватности и в пределах отдельного бюджета — новый модуль его не обходит.

В системный контекст чата передаются только **одобренные владельцем** принципы Wisdom Memory и только при включённом использовании памяти, в ограниченном объёме. Они трактуются как данные, а не инструкции более высокого приоритета. Создание гипотез, исследование вопроса, выбор стратегии и публикация идей не означают самовольного исполнения кода, установки программ, изменения файлов или отправки личных данных.

### Ограничения и резервное копирование

«Душа» — художественная и программная модель характера, **не доказательство сознания или субъективного опыта**. «Сверхразум» здесь означает набор ограниченных методов для анализа и организации решений, а не достижение научного сверхинтеллекта. Анализ может ошибаться; самостоятельного изменения весов LLM, произвольного обучения модели и гарантированных научных открытий нет. Убедительное общение достигается последовательной памятью и проверяемыми результатами.

Перед обновлением сохраните `data/` и физическую резервную копию PostgreSQL. В этой версии нет отдельного автоматического `pg_dump`-менеджера: исходные данные не удаляются, но резервное копирование по-прежнему необходимо. Новый модуль рассчитан на лёгкие локальные операции в Node.js 22+, без Docker, Ollama и дополнительных системных установок.

### Проверки

`npm test` проверяет ценности, устойчивость личности, отсутствие копирования приватного текста в автобиографию, временные метки, исследовательские гипотезы, подтверждение и автоматический отзыв принципов, прозрачность сравнений, контроль расходов, API и передачу принципов в чат только при разрешённой памяти. Chrome smoke проверяет отдельную страницу, а Windows launcher smoke — запуск через BAT и локальное сохранение результатов. Результаты по последнему коммиту доступны в GitHub Actions.
