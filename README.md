# Tsukirei / Цукирэй

Локальное персональное ИИ-пространство для Windows: чат Cloud.ru, заметки, задачи и **PostgreSQL + pgvector с автоматической установкой из одного BAT**.

## Автоматический запуск Windows x64 (ничего отдельно устанавливать не нужно)

1. Скачайте [ZIP проекта](https://github.com/Aspksa/Tsukirei/archive/refs/heads/main.zip) и распакуйте на Windows (можно на внешний M.2 SSD).
2. Дважды запустите **`Tsukirei.bat`**.
3. BAT сам проверит Node.js и при необходимости установит переносимый Node.js. Затем загрузит и проверит SHA-256 переносимого **PostgreSQL 18 + pgvector 0.8.5** в составе [pg0 v0.16.1](https://github.com/vectorize-io/pg0/releases/tag/v0.16.1), создаст базу `tsukirei` с уникальным локальным паролем и откроет сайт.
4. Сайт доступен по адресу `http://127.0.0.1:3000` (или первый свободный порт 3001–3020). Закрытие BAT останавливает сервер Tsukirei и пытается корректно остановить PostgreSQL.

**Docker, системная служба PostgreSQL, Python и права администратора не нужны** на протестированной Windows x64 с доступной для записи NTFS-папкой. Интернет нужен при первом скачивании Node.js и pg0. Cloud.ru подключается отдельно через настройки чата.

### Где физически хранится база

На Windows с кириллицей в пути PostgreSQL не всегда может инициализироваться внутри самой папки проекта. Поэтому BAT создаёт **настоящий латинский каталог на том же диске**: `Tsukirei-Postgres-<идентификатор>`. Он располагается в ближайшей доступной для записи родительской папке с латинским путём, то есть может находиться **вне каталога Tsukirei**, но не на другом диске и не в облаке.

Расположение автоматически записывается в `data/portable-postgres.json` и отображается в окне BAT. **Не удаляйте этот каталог, не форматируйте диск и не копируйте один лишь каталог Tsukirei при переносе на другой компьютер: вместе с ним нужно сохранить каталог PostgreSQL.** Если буква внешнего диска поменялась, восстановите прежнюю букву или скорректируйте путь в конфигурации после остановки БД. Не копируйте каталог работающей БД; для её резервирования используйте `pg_dump`.

Если диск отформатирован в exFAT/FAT или права NTFS не позволяют корректно инициализировать PostgreSQL, BAT выведет ошибку вместо скрытого перехода на JSON. В тестах GitHub Actions проверены настоящий запуск PostgreSQL, запись заметок, создание вектора и поиск с `pgvector` на Windows в папке с русскими и специальными символами.

### Если PostgreSQL уже есть

Можно вместо автоматической установки задать `TSUKIREI_DATABASE_URL` или заполнить `data/postgres-settings.json` вручную. При наличии пользовательского подключения (без `data/portable-postgres.json`) BAT не скачивает и не запускает pg0. Для облачной/удалённой БД используйте TLS.

## Как подключить PostgreSQL + pgvector вручную


1. Подготовьте работающий PostgreSQL с расширением [pgvector](https://github.com/pgvector/pgvector). Он может работать локально либо на другом доступном сервере. Для работы **полностью с внешнего SSD** PostgreSQL должен хранить свои файлы данных на этом SSD; одно лишь расположение файлов Tsukirei на SSD не переносит базу автоматически.
2. Создайте отдельную БД `tsukirei`, пользователя с правами на таблицы. Включите расширение `CREATE EXTENSION vector;` от пользователя, имеющего соответствующие права, или дайте приложению разрешение создать его при первом запуске.
3. В каталоге `data/` создайте **локальный**, не отслеживаемый Git файл `postgres-settings.json`:

```json
{
  "url": "postgresql://USER:PASSWORD@127.0.0.1:5432/tsukirei"
}
```

4. Запустите `Tsukirei.bat`. Сервер автоматически создаст `tsukirei_state`, `tsukirei_knowledge` и индексы. В интерфейсе появится статус `Память: PostgreSQL + pgvector`.

Также можно установить `TSUKIREI_DATABASE_URL` либо `DATABASE_URL` в окружении. **Не публикуйте URL с паролем и не коммитьте папку `data/`.** Для удалённой БД используйте TLS/SSL. Если PostgreSQL включён, а затем недоступен, Tsukirei сообщает об ошибке вместо тихого использования устаревшего JSON.

## Миграция с JSON без потери данных

При первом подключении PostgreSQL сервер переносит в таблицу `tsukirei_state` данные из `data/tsukirei.json`: заметки, задачи и все **сохранившиеся** сообщения. Перед импортом создаётся отдельная резервная копия `data/backups/tsukirei-before-postgres-*.json`; исходный файл остаётся неизменным.

**Важное ограничение:** в старой версии хранились лишь последние 250 сообщений — ранее удалённые записи нельзя восстановить автоматически. PostgreSQL хранит полную новую историю, хотя интерфейс пока загружает только последние 250 сообщений. Отдельный маркер `data/postgres-active.json` предотвращает непреднамеренное возвращение к устаревшему JSON, если настройки подключения исчезнут.

## База знаний и поиск

- `tsukirei_state` — основное состояние приложения в JSONB; запись защищена транзакцией PostgreSQL и блокировкой строки от параллельных изменений.
- `tsukirei_knowledge` — база знаний с `content`, `source`, `metadata` и необязательным `embedding vector`.
- Полнотекстовый поиск через PostgreSQL и сравнение эмбеддингов косинусным расстоянием (`<=>`). Для 1024-мерных векторов имеется HNSW-индекс; другие размерности ищутся без этого индекса.

API: `POST /api/knowledge` принимает `content`, необязательные `source`, `metadata`, `embedding` и `embeddingModel` (если указан вектор). `POST /api/knowledge/search` принимает `query` или `embedding` и `limit` (1–100). `GET /api/state` сообщает текущее хранилище в поле `database`.

Автоматическая генерация эмбеддингов и граф знаний **пока не реализованы**. Текстовый поиск и запись знаний не отправляют запросы в Cloud.ru.

## Файлы

| Путь | Содержимое |
| --- | --- |
| `data/tsukirei.json` | Исходный JSON, используется пока PostgreSQL не настроен |
| `data/backups/` | JSON-копия перед миграцией |
| `data/postgres-settings.json` | Пароль и URL подключения к PostgreSQL — только локально |
| `data/portable-postgres.json` | Настройки автоматически созданного PostgreSQL: порт, пароль и путь к данным |
| `Tsukirei-Postgres-<идентификатор>/` | Физические файлы PostgreSQL на том же диске; расположение показано в BAT |
| `data/postgres-active.json` | Маркер миграции/защиты от отката к JSON |
| `data/cloudru-settings.json` | Локальный API-ключ и модель Cloud.ru |
| `.runtime/` | Переносимый Node.js и npm-кэш |
| `logs/` | Журналы BAT |

**При автоустановке файлы PostgreSQL всегда остаются на диске проекта, но могут находиться в отдельной папке рядом с ним или выше по дереву.** Копия только `data/` не является полной резервной копией PostgreSQL; используйте `pg_dump`.

## Разработка и тестирование

```sh
npm ci
npm run check
npm test
npm run dev
```

Для интеграционного теста задайте **тестовую отдельную** `TSUKIREI_DATABASE_URL` и выполните `npm run test:postgres`. Интеграционный тест выполняет операции записи/удаления в БД и не должен запускаться против пользовательской рабочей БД.

GitHub Actions проверяет полную автоматическую установку PostgreSQL + pgvector из BAT на Windows (включая пути с кириллицей), запись и векторный поиск, API на Windows и Linux, а также независимый интеграционный тест PostgreSQL + pgvector на Ubuntu без Docker.

`Tsukirei.bat --diagnose` — диагностика окружения, `--no-open` — запуск без открытия браузера.

## Город памяти v0.3 — как работает

Открывается отдельной кнопкой **Город памяти** в левой панели либо нажатием на сферу на главной.

- Источники: **реальные локальные заметки и история чата**, уже имеющиеся в приложении; задачи сюда не попадают.
- Одно здание соответствует одной заметке или одной реплике пользователя со следующим ответом модели (если он существует). Осиротевший ответ также имеет отдельное здание.
- Район — определённая локальным словарём тема. Для текстов вне словаря используется первое значимое слово заголовка. Это автоматическая **эвристика**, а не глубокое семантическое понимание.
- Высота зданий отражает количество значимых слов в сохранённом тексте (логарифмическая шкала); не является метрикой интеллекта.
- Дороги между районами возникают только при совпадении значимых слов. Это лексическая связь, а не доказательство смысловой причинно-следственной связи.
- Наведение и клик на здание открывают его исходный текст и переход к заметке или чату. Районы доступны также с клавиатуры через список справа.
- Мышь: перетаскивание — панорама, колесо — масштаб; клавиатура на Canvas: стрелки и +/-; кнопка «Показать весь город» восстанавливает масштаб.
- Город автоматически пересобирается после сохранения и удаления записей, открытия диалога или очистки истории. Сведения в Cloud.ru не отправляются, генерация не вызывает ИИ. 
- Пустое хранилище — **пустой город**, без фиктивных зданий. В PostgreSQL-режиме используется архив, переданный в /api/state (до 250 сообщений текущего UI); весь архив физически хранится в PostgreSQL, но ещё не весь подгружается в город.

Рендерер — нативный Canvas 2D с изометрической проекцией, без обязательных 3D-библиотек, GPU-моделей и внешних CDN. Это псевдо-3D, не полноценная WebGL-сцена. Нагрузка зависит от числа записей. Предусмотрена проверка модели города и HTTP-маршрутов в GitHub Actions.


## Город памяти v0.4 — настоящий 3D и полный архив

- **3D через WebGL2:** объёмные здания с фасадами и светящимися окнами, перспективная камера, аппаратный instancing для большого числа зданий. Использует установленный браузер; не требует отдельной локальной ИИ-модели, WebGL-библиотек или CDN.
- **Полный архив без ограничения 250 диалоговых сообщений:** при открытии города браузер последовательно запрашивает страницы максимум по 200 записей через GET /api/city/archive?kind=notes|messages|knowledge&offset=0&limit=200.
- В PostgreSQL заметки и сообщения выбираются частями из JSONB, а самостоятельные знания — из tsukirei_knowledge. В режиме старого JSON также доступно постраничное чтение заметок и сообщений. Источник данных не изменяется и не удаляется.
- **Группировка:** категории определяются локально по ключевым словам, остальные темы — по первой букве слова. Дороги показывают общие слова, **не подтверждённые семантические отношения**. Высота зданий зависит от числа значимых слов.
- **Управление:** левая кнопка + движение — вращение; правая кнопка (либо Shift) + движение — перемещение; колесо — приближение; клик по зданию — реальные данные; кнопки справа — приближение/отдаление/общий вид. Доступен переход в исходную заметку и чат.
- При отсутствии WebGL2 применяется прежний облегчённый 2D-рендерер.
- Загрузка происходит только при входе в раздел; новые заметки и ответы чата делают кеш города устаревшим и вызывают перечитывание данных, если город открыт. Ни визуализация, ни чтение архива **не вызывают Cloud.ru**.
- Для больших архивов браузер должен загрузить весь текст в память, поэтому потребление ОЗУ увеличивается с объёмом данных. Потоковая геометрия и серверные кластеры для миллионов записей пока не реализованы.
- Город не показывает удалённые диалоги или знания, отсутствующие в локальном PostgreSQL/JSON. Это визуализация существующих данных, а не автоматическое создание новых воспоминаний.

### Контроль качества

Запускаются тесты на Windows и Linux: проверка серверного API, полной выборки из 625 сообщений, границ страниц, запрета внешнего Origin, загрузки WebGL-файлов, PostgreSQL и pgvector. Дополнительно GitHub Actions запускает Google Chrome в headless-режиме с программным WebGL2 и проверяет настоящий 3D-город, загрузку локального архива, отсутствие JavaScript-исключений и ошибок WebGL. Результат в CI не гарантирует совместимость с видеодрайвером на каждом пользовательском компьютере.

## Tsukirei v0.5 — оптимизация больших городов памяти

Все оригинальные данные остаются в PostgreSQL + pgvector (либо в старом локальном JSON). Новый режим просмотра оптимизирует передачу и отображение **без удаления или обрезания оригинальных записей**.

- GET /api/city/archive?...&compact=1 передаёт названия, короткие фрагменты (до 650 символов) и реальную длину исходного текста. Прежний полный API также доступен.
- GET /api/city/entry?kind=notes|messages|knowledge&id=... отдаёт полный оригинал только по нажатию «Прочитать полный текст». Ключ Cloud.ru в браузер не передаётся.
- Постраничная загрузка по 200 объектов. Здания отображаются постепенно; полная пересборка проводится примерно после 400, 800, 1600, 3200 и т. д. записей, а затем ещё раз по завершении.
- При выходе из города до завершения чтения старые запросы перестают добавлять данные. При повторном открытии запускается новая загрузка.
- Высота зданий зависит от оригинальной длины текста, даже если в браузер отправлен только фрагмент.
- WebGL отключает прорисовку мелких окон фасадов при большом отдалении или огромном числе зданий, сохраняя здания и исходные записи.
- В боковой панели доступен поиск по названиям и загруженным фрагментам. Можно приблизиться к найденному зданию. Это пока не полнотекстовый поиск по всей базе.
- Построение, поиск и визуализация выполняются локально без дополнительных вызовов Cloud.ru.

### Производительность и ограничения

Даже сокращённые данные всех записей загружаются в память браузера, поэтому использование RAM растёт с размером архива. Эта реализация не заменяет серверное пространственное индексирование миллионов объектов. FPS и объём памяти на конкретном ноутбуке можно установить только локальной проверкой. Автоматические тесты проверяют построение 10 000 зданий из 12 000 архивных сообщений/заметок, WebGL2 в Chrome и восстановление исходного текста по запросу.
