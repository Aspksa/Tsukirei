# Tsukirei / Цукирэй

Локальное персональное ИИ-пространство для Windows: **PostgreSQL + pgvector**, Cloud.ru, заметки, дела, архив диалогов и база знаний. Запускается одним `Tsukirei.bat` без Docker, Python и прав администратора.

## Быстрый запуск Windows x64

1. Скачайте архив: https://github.com/Aspksa/Tsukirei/archive/refs/heads/main.zip
2. Распакуйте на обычный диск или внешний M.2 SSD.
3. Дважды нажмите `Tsukirei.bat`.
4. При первом запуске BAT установит переносимый Node.js (если его нет) и npm-зависимости, а затем скачает **pg0 v0.16.1** с закреплённой SHA-256, запустит локальный PostgreSQL с pgvector и откроет сайт.
5. Адрес по умолчанию: http://127.0.0.1:3000. Если он занят, BAT выберет 3001–3020.

При первом запуске нужен интернет для загрузки компонентов. PostgreSQL работает локально — без Cloud.ru и без Docker. Для ИИ-ответов ключ Cloud.ru добавляется отдельно в интерфейсе.

**Источник переносимого сервера:** [vectorize-io/pg0](https://github.com/vectorize-io/pg0), релиз [v0.16.1](https://github.com/vectorize-io/pg0/releases/tag/v0.16.1). Windows-бинарник `pg0-windows-x86_64.exe` закреплён SHA-256 `da580cc8fd390ba01158bea192d6bb6d4b0f583abc468ced7f9c582370c34cb6`. Это сторонний открытый проект, а не официальный установщик PostgreSQL. При желании можно использовать собственный PostgreSQL + pgvector вместо pg0.

## База данных

В режиме PostgreSQL заметки, задачи и **полная сохранённая история новых диалогов** записываются в таблицу `tsukirei_state` (JSONB); приложение показывает в интерфейсе последние 250 сообщений, но в PostgreSQL хранит весь архив. Отдельная таблица `tsukirei_knowledge` хранит знания, метаданные и векторные эмбеддинги pgvector. Созданы GIN-индекс для текстового поиска и HNSW для векторов размерности 1024. Другие размерности поддерживаются точным поиском, пока не добавлен соответствующий индекс.

При первом подключении PostgreSQL:

- BAT создаёт отдельную базу и случайный пароль для локального пользователя.
- Сервер создаёт расширение `vector` и необходимые таблицы.
- Если был `data/tsukirei.json`, переносит **все сохранившиеся в этом файле** заметки, задачи и сообщения.
- Перед переносом копирует исходный JSON в `data/backups/`. Оригинал остаётся нетронутым.
- В `data/postgres-active.json` создаётся маркер: если настройки БД позже пропадут, сервер сообщит об ошибке, а не переключится незаметно на старые данные.

**Важно:** более ранние версии сохраняли только последние 250 сообщений; удалённые ранее сообщения не могут быть восстановлены миграцией. Текущие таблицы `tsukirei_state` / `tsukirei_knowledge` — начальная структура PostgreSQL; специализированные таблицы для сообщений, граф знаний и автоматические эмбеддинги — следующие этапы.

### Локальные пути

| Путь | Назначение |
| --- | --- |
| `data/postgres/` | Реальные данные PostgreSQL — **не удалять** |
| `.runtime/pg0-home/` | Переносимая установка и служебные файлы PostgreSQL |
| `.runtime/pg0/pg0.exe` | Проверенный переносимый исполняемый файл pg0 |
| `data/portable-postgres.json` | Параметры локальной PostgreSQL; содержит пароль |
| `data/postgres-settings.json` | Строка подключения; содержит пароль |
| `data/postgres-active.json` | Защита от случайного перехода на устаревший JSON |
| `data/backups/` | Сохранённая копия JSON перед переносом |
| `data/cloudru-settings.json` | API-ключ Cloud.ru, никогда не загружается в Git |
| `logs/` | Журналы запуска |

Все файлы базы и программы находятся в папке проекта. Внешний M.2 должен быть подключён при работе; **нельзя перемещать каталог с работающим PostgreSQL**. Для безопасного переноса остановите БД и приложение и перенесите обе папки `data/` и `.runtime/` вместе. Не копируйте работающий каталог PostgreSQL как резервную копию: для штатных резервных копий нужен `pg_dump`.

## Подключение существующего PostgreSQL

Если PostgreSQL + расширение `vector` уже установлены (локально либо на управляемом сервере), создайте `data/postgres-settings.json` вручную:

```json
{"url":"postgresql://USERNAME:PASSWORD@127.0.0.1:5432/tsukirei"}
```

Или задайте `TSUKIREI_DATABASE_URL` в окружении. BAT не станет скачивать pg0 при внешней конфигурации. У пользователя БД должны быть права на `CREATE EXTENSION vector` (либо расширение должно быть заранее включено) и `CREATE TABLE`. Если соединение не удалось, приложение остановится с ошибкой — **без тихого возврата на JSON**.

Для удалённой БД включите SSL/TLS и отдельного пользователя с минимально необходимыми правами. Строку подключения не размещайте в GitHub и не передавайте третьим лицам.

На Windows ARM64 и 32-битных системах автоматическая загрузка pg0 недоступна; настройте совместимый PostgreSQL вручную.

## API базы знаний

Знания пока добавляются программно и не извлекаются из чата автоматически. Cloud.ru не вызывается при записи/поиске в базе знаний.

- `POST /api/knowledge` — JSON с `content`, необязательными `source`, `metadata`, `embedding` и обязательным `embeddingModel` при передаче эмбеддинга.
- `POST /api/knowledge/search` — JSON с `query` (текстовый поиск) или `embedding` (косинусное сходство), необязательным `limit` (1–100).
- `GET /api/state` — данные для интерфейса и поле `database` с актуальным статусом.

## Команды

- `Tsukirei.bat` — запустить всё на Windows x64.
- `Tsukirei.bat --diagnose` — проверить окружение без запуска.
- `Tsukirei.bat --no-open` — не открывать браузер.
- `TSUKIREI_NO_AUTO_POSTGRES=1` — отключить автоустановку PostgreSQL для отладки старого JSON-режима (нельзя использовать для обхода уже активированной БД).
- `TSUKIREI_PORT` — фиксированный HTTP-порт вместо 3000.

Для разработки на Node.js 22.18+ (при подключённом PostgreSQL или тестовом legacy JSON):

```sh
npm ci
npm run check
npm test
npm run dev
```

Для интеграционных тестов задайте отдельную тестовую `TSUKIREI_DATABASE_URL`, затем `npm run test:postgres`. В GitHub Actions настоящий PostgreSQL + pgvector тестируется на Ubuntu **без Docker**, а переносимый BAT — на Windows с кириллицей и специальными символами в пути.

## Ограничения текущей версии

- Автоматическая генерация эмбеддингов через Cloud.ru и граф связей пока не реализованы.
- PostgreSQL хранит основной архив, но интерфейс пока отображает только последние 250 сообщений.
- Автоматического расписания `pg_dump` и восстановления из него пока нет.
- Локальный HTTP-сервер слушает только `127.0.0.1`; доступ из интернета не предусмотрен.
